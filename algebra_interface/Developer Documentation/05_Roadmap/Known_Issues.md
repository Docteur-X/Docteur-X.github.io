# Known issues and limitations

**Minor visual issues reported by the owner:** equality insertion preview resting amber border consistency; optional excessive grouping around atomic factors; crowded factorisation extraction zone sometimes inaccessible while the toolbar's Preview Extraction works. Determine whether the last case is deliberate crowded-layout suppression before changing geometry.

**Architecture:** publication is failure-safe preparation followed by synchronous assignments, not a universal transaction. `app.js` still coordinates some feature-specific interactions. Proposal metadata has transitional compatibility shapes; not all preview families use the shared semantic feedback path. One active mathematical view is assumed.

**Negation/subtraction:** scalar-only validity assumptions; future powers require explicit precedence/associativity rules. Compression eligibility during pointer movement can construct detached candidates repeatedly. No performance measurements currently justify optimization; a future lightweight eligibility-only proposal may be appropriate if profiling shows a problem. Negative numerical literals remain atomic by default; structural negation is deliberately distinct. v1.2.3 browser verification pending; v1.2.2 was owner-verified.

**Future capabilities:** no general type/domain/assumption engine, division, powers, logical contexts, general substitution, matrices/vectors, resizable multi-view windows or annotation layer. No measured low-end-device performance guarantees. Large history cloning and large-expression overflow warrant benchmarks/design work when relevant.

These are follow-ups, not proof of a regression. Reproduce before changing code, and update this maintained list in place.
